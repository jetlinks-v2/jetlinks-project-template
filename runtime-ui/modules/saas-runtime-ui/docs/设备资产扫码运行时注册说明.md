# 设备资产扫码运行时注册说明

## 设备列表“接入网关”入口恢复（2026-09-22）

目标：在 SaaS 资源中心“设备列表 → 边缘节点”恢复右上角“接入网关”，点击后只展示已有的扫码提示框，不进行手工新增或设备写入。影响范围为本模块 `index.ts#getRegisterComponents` 的工具栏隐藏策略；按钮和弹窗仍由 `edge-master-ui/deviceListProvider.ts` 与 `GatewayAccessModal.vue` 提供，统一列表仍由 `device-manager-ui/views/device/list/unified/index.vue` 承载。

实施：移除 SaaS 对 `unified-device-list:toolbar-actions` 中 `create-gateway` 的隐藏注册，保留其他注册项、页面结构、筛选和批量操作；将 `edge-master-ui` 共用的接入按钮中英文文案统一为“接入网关 / Connect Gateway”，补充策略和文案回归检查。风险与验证：确认 SaaS 不再过滤目标按钮，网关 Provider 仍使用原有扫码弹窗且不要求新增权限；运行时页面需刷新／重新部署以验证按钮显示和弹窗交互。依照本机性能约束，不运行整个前端构建。

验证结果：`node --test modules/saas-runtime-ui/tests/gateway-access-entry.test.mjs modules/edge-master-ui/tests/gatewayAccessGuide.test.mjs` 共 5 项通过；本机已运行的 Chrome `http://localhost:9200/#/resources/devices/list?type=gateway` 实际显示“批量操作”右侧的蓝色“接入网关”，点击弹出扫码说明和标签示意图，“我知道了”关闭后按钮仍在。未触发设备写入；未运行全量构建、类型检查或 lint。上线环境仍需发布当前 `saas-runtime-ui` 与 `edge-master-ui` 前端资源，后端不变。

## 当前结论

设备资产扫码接入页位于 `views/scan/Product/index.vue`，页面通过 `views/scan/Product/hooks/useScanProductAccess.ts` 读取扫码参数并完成产品准备、设备注册和设备启用。

扫码完成态调整：保留现有成功卡片、网关名称及项目摘要，增加带电脑图标的查看指引和“你可以关闭此页面”提示；移除成功态底部“完成”按钮及 `finish` 跳转逻辑。页面停留在接入完成态，用户前往电脑端打开对应项目查看网关；新增文案使用模块中英文资源。仅调整当前扫码接入页的完成态，不改注册、启用流程和其他扫码路由。

本次注册接口 payload 仅保留运行时注册所需字段：

- `scanToken`：扫码令牌，来自路由参数 `t` 或 `scanToken`。
- `productId`：已准备好的接入产品 ID。
- `device.name`：网关名称。
- `device.description`：网关备注。

`projectId` 与 `projectName` 不再随 `/device/asset/access/_register` 请求提交。`projectName` 仍从路由参数读取，仅用于扫码页顶部、加载态和成功态中的项目名称展示。

## 影响范围

Owning module：`runtime-ui/modules/saas-runtime-ui`

关键代码入口：

- `api/device.ts`：定义 `RegisterDevicePayload`、`RegisterDeviceResponse`，并收紧 `registerDevice` 入参类型。
- `views/scan/Product/hooks/useScanProductAccess.ts`：组装注册 payload，移除 `projectId`、`projectName`，保留 `projectName` 展示计算逻辑。
- `views/scan/Product/index.vue`：消费 hook 返回的 `projectName` 做页面展示，成功态补充电脑端查看指引并隐藏底部操作栏。
- `views/scan/Product/components/Save.vue`：新增产品后回到扫码产品列表时保留 `returnUrl`。
- `package.json`：修正模块内 `dev/build` 脚本，指向当前工作区真实核心包 `jetlinks-web-core` 和目录名 `saas-runtime-ui`。
- `register.ts`：补齐模块构建入口，当前仅导出空注册项，不改变运行时注册业务。

## 行为说明

扫码页初始化时仍会按现有流程检查扫码令牌、查找或创建网关接入产品，并在用户确认后调用设备资产注册接口。注册成功后继续尝试启用设备，随后停留在接入完成页，提示用户前往电脑端查看。成功态不再提供跳转按钮，也不读取 `returnUrl` 执行页面跳转。

注册接口不再依赖页面路由中的项目 ID 或项目名称，避免展示态参数混入后端注册契约。项目名称只作为用户确认当前扫码上下文的展示信息。
