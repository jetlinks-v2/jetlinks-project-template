# 巡检应用示例实现

班组维度把用户和业务数据关联起来：用户加入班组，计划通过 `inspectionTeamId` 归属班组，角色选择“所在巡检班组”后，由平台资产权限过滤数据。

**当前限制：自定义维度暂不支持下级资产控制。** 示例中的 `tree`、`includeChildren` 用于班组维度节点的层级与范围解析，不代表下级资产控制能力。

## 模块与数据

| 模块 | 职责 |
| --- | --- |
| [demo-manager](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo) | 班组、计划 CRUD，成员管理，维度同步和配额 |
| [demo-service](../microservices/demo-service/src/main/java/org/jetlinks/pro/demo/DemoApplication.java) | 独立启动和装配 |
| [jetlinks-demo-ui](../runtime-ui/modules/jetlinks-demo-ui) | 班组、计划页面；[API](../runtime-ui/modules/jetlinks-demo-ui/api/index.ts) 调用 demo 后端 |

| 业务表 | 关键字段 |
| --- | --- |
| `demo_inspection_team` | `id`、`name`、`parentId`、`state` |
| `demo_record` | `id`、`name`、`inspectionTeamId`、`inspectionItems` |

班组的 `parentId` 是上级班组业务 ID，状态默认 `enabled`。计划必须选择负责班组，清单至少一项，每项包含名称 `name` 和检查要求 `requirement`；清单按 JSON 存储。两实体都有平台填写的只读 `creatorId`、`createTime`，用于“自己创建的”范围。

下面代码为当前实现节选，省略 import 和无关成员，完整实现见链接。

## 后端接入班组维度

### 1. 先接入资产 CRUD

在 [DemoAssetType](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/asset/DemoAssetType.java) 中定义 `demo-inspection-team`、`demo-record` 两种资产，权限使用 `CrudAssetPermission`。

[班组实体](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/entity/DemoInspectionTeamEntity.java) 和 [计划实体](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/entity/DemoRecordEntity.java) 继承 `ExtendableEntity<String>`、实现 `RecordCreationEntity`，标记 `@Asset(type = 对应资产类型)` 和 `@EnableEntityEvent`。[DemoAssetSupplier](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/asset/DemoAssetSupplier.java) 实现 `AssetSupplier`，向平台注册这两类资产，按 ID 查询实体后返回 `DefaultAsset.withEntity(entity)`。

[班组控制器](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/controller/DemoInspectionTeamController.java) 接入标准资产 CRUD：

```java
@RestController
@RequestMapping("/demo/inspection-team")
@Resource(id = DemoAssetType.TEAM_TYPE_ID, name = "巡检班组")
@AssetsController(type = DemoAssetType.TEAM_TYPE_ID)
@AllArgsConstructor
@Getter
public class DemoInspectionTeamController implements AssetsHolderCrudController<DemoInspectionTeamEntity, String> {
    private final DemoInspectionTeamService service;
}
```

计划控制器同样接入，路径为 `/demo/record`，资源标识为 `demo-record`。`@Resource` 管功能权限，`AssetsHolderCrudController` 配合 `@AssetsController` 管资产数据权限。

### 2. 声明“班组”维度类型

在 [DynamicDimensionTypeEntity.entity.json](../modules/examples/demo-manager/src/main/resources/auto-init/DynamicDimensionTypeEntity.entity.json) 声明：

```json
[
  {
    "id": "demo-inspection-team",
    "name": "巡检班组",
    "owner": ["demo"],
    "state": "enabled",
    "features": ["tree", "userBinding", "dataAccess", "includeChildren"],
    "dataAccessConfig": {
      "name": "所在巡检班组",
      "assetTypes": ["demo-record", "demo-inspection-team"]
    }
  }
]
```

平台据此识别维度类型，生成范围 `dynamic_demo-inspection-team`，用于班组和计划两类资产。初始化配置见后文。

### 3. 保存班组时同步维度实例

编写 [DemoInspectionTeamLifecycleHandler](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/event/DemoInspectionTeamLifecycleHandler.java)，注册为 `@Component`，注入班组 Repository 和 `DynamicDimensionService`。保存事件调用同步方法：

```java
@EventListener
public void afterSave(EntitySavedEvent<DemoInspectionTeamEntity> event) {
    if (event.getEntityType() == DemoInspectionTeamEntity.class) {
        event.async(synchronize(event.getEntity()));
    }
}

private Mono<Void> synchronize(Collection<DemoInspectionTeamEntity> input) {
    List<String> ids = input.stream().map(DemoInspectionTeamEntity::getId).distinct().toList();
    return teams.findById(ids).map(team -> {
        DynamicDimensionEntity dimension = new DynamicDimensionEntity();
        dimension.setTypeId(DemoAssetType.TEAM_TYPE_ID);
        dimension.setDimensionId(team.getId());
        dimension.setName(team.getName());
        dimension.setState(team.getState());
        dimension.setParentId(StringUtils.isBlank(team.getParentId()) ? ""
            : AssetsUtils.createBindingTargetKey(DemoAssetType.TEAM_TYPE_ID, team.getParentId()));
        return dimension;
    }).collectList().flatMap(dimensions::save).then();
}
```

新增、修改事件也调用此方法；删除事件按组合键删除维度实例。业务表保存班组信息，维度实例供权限计算使用：

- `dimensionId`：班组业务 ID。
- 实例主键：`AssetsUtils.createBindingTargetKey(typeId, 班组ID)`。
- 实例 `parentId`：父实例组合键。

该监听器还检查上级班组有效且可保存，删除时没有子班组或计划引用。`event.async` 将同步操作接入实体事件执行链。

### 4. 告诉平台“哪些数据属于这个班组”

本例有两条字段映射：

| 资产 | 对应班组维度的字段 | 当前实现 |
| --- | --- | --- |
| 巡检计划 `demo-record` | `inspectionTeamId` | Direct 的 YAML 声明 |
| 巡检班组 `demo-inspection-team` | 自身 `id` | Java Provider，关系只读 |

计划在新增或更换负责班组时保存 `inspectionTeamId`。[DemoRecordLifecycleHandler](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/event/DemoRecordLifecycleHandler.java) 在写入前校验目标班组存在、维度启用，并调用 `AssetsHolder.assertPermission(DemoAssetType.inspectionTeam, changedTeams, CrudAssetPermission.save)`。其他字段更新保留原归属。

班组自身由 [DemoInspectionTeamAssetBindProvider](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/asset/DemoInspectionTeamAssetBindProvider.java) 提供查询映射：

```java
private static final Map<String, String> SELF_DIMENSION = Map.of(DemoAssetType.TEAM_TYPE_ID, "id");

public DemoInspectionTeamAssetBindProvider(ReactiveRepository<DemoInspectionTeamEntity, String> repository) {
    super(repository, DemoAssetType.TEAM_TYPE_ID, SELF_DIMENSION);
}

@Override
public Collection<TermFragmentBuilder> createTermBuilders(String tableName, String assetType) {
    if (!DemoAssetType.TEAM_TYPE_ID.equals(assetType)) {
        return List.of();
    }
    return List.of(new SimpleDirectAssetsTermFragmentBuilder(assetType, tableName, SELF_DIMENSION));
}
```

该类继承 `DirectAssetBindProvider`、实现 `AssetTermBuilderProvider`，并标记 `@Component`。它重写绑定、解绑方法，不执行字段更新，保证自身映射不会改动班组主键。

### 5. 将应用用户加入班组

[成员控制器](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/controller/DemoInspectionTeamMemberController.java) 委托 [DemoInspectionTeamMemberService](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/service/DemoInspectionTeamMemberService.java)。绑定方法为：

```java
public Mono<Void> bind(String teamId, List<String> userIds) {
    return validateUserIds(userIds)
        .flatMap(ids -> assertTarget(teamId, Permission.ACTION_SAVE, CrudAssetPermission.save)
            .flatMap(applicationId -> assertApplicationMembers(applicationId, ids))
            .then(Mono.defer(() -> {
                List<DimensionUserBinding> members = ids.stream().map(userId -> {
                    DimensionUserBinding binding = new DimensionUserBinding();
                    binding.setUserId(userId);
                    binding.setDimensionTypeId(DemoAssetType.TEAM_TYPE_ID);
                    binding.setDimensionId(teamId);
                    return binding;
                }).toList();
                return CommandSupportManagerProviders.getCommandSupport(SdkServices.authService)
                    .flatMap(support -> support.execute(new BindDimensionUsersCommand().setBindings(members)))
                    .then();
            })));
}
```

这里的校验方法属于本例 Service：

- `assertTarget`：校验当前应用 Scope、班组功能和资产权限、维度可绑定用户，以及租户和当前应用归属。
- `assertApplicationMembers`：确认所选用户都属于当前应用，并通过 `AssetsHolder.injectQueryParam(query, "user", "id")` 限定用户资产范围。

已加入、可添加列表分别固定当前应用与班组条件，再执行认证服务查询命令。移出使用 `UnbindDimensionUsersCommand`，明确限定类型、班组和用户。

独立服务通过 [DemoAuthenticationDimensionSource](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/configuration/DemoAuthenticationDimensionSource.java) 核验认证快照中的班组关系；[DemoApplication](../microservices/demo-service/src/main/java/org/jetlinks/pro/demo/DemoApplication.java) 使用 `@Import` 装配它。此查询需要 `user/query` 权限。

### 6. 配置角色使用这个范围

[baseMenu.json](../runtime-ui/modules/jetlinks-demo-ui/baseMenu.json) 声明菜单资产并开启 `supportDataAccess`。角色给 `demo-record`、`demo-inspection-team` 选择“所在巡检班组”；应用模板需允许范围 `dynamic_demo-inspection-team`，角色授权同时受授权人自身可授范围约束。

查询经 `AssetsHolder` 结合成员关系和第 4 步映射执行。绑定成员与角色数据授权分别完成；“自己创建的”是另一项独立范围。成员管理需要班组保存、用户查询及维度保存／删除权限。

## 启动配置放在一处

[application.yml](../microservices/demo-service/src/main/resources/application.yml) 中与本例维度有关的配置集中如下：

```yaml
jetlinks:
    auto-init:
        enabled: true
        strategy:
            DynamicDimensionTypeEntity.entity.json: increment
    assets:
        asset-tables:
            demo_inspection_team: demo-inspection-team
        direct:
            enabled: true
            tables:
                demo_record:
                    asset-type: demo-record
                    dimension-column:
                        demo-inspection-team: inspectionTeamId
```

| 配置 | 作用 |
| --- | --- |
| `auto-init` | 服务启动时加载维度类型 JSON |
| `assets.asset-tables` | 将班组表名关联到资产类型，供条件构造使用 |
| `assets.direct` | 根据计划字段生成资产与班组维度的关联能力 |

`auto-init.enabled` 和 `direct.enabled` 是当前自动装配开关；`strategy` 显式选择增量初始化。班组表映射供自身查询条件注册使用，实体的 `@Asset` 不会自动完成这项注册。计划采用配置式 Direct，班组自身采用只读 Provider。

## 清单项配额

[DemoInspectionItemsQuotaLimiter](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/limiter/DemoInspectionItemsQuotaLimiter.java) 继承 `EntityEventQuotaLimiter<DemoRecordEntity, String>`，实现 `AssetResourceMetric`。指标是 `MetricId.of(DemoAssetType.record.getId(), "inspectionItems")`，名称“巡检项保有量”，单位“项”，限制类型 `quotaLimit`。

单条计划用量取真实清单项数：

```java
@Override
protected double getUsage(DemoRecordEntity entity) {
    return entity.getInspectionItems().size();
}
```

Save 路径的 `handleBeforeSave` 汇总新项数，调用 `countById` 锁定并累计旧项数，再按差额调整：

```java
return TenantHolder.getReactive(tenantId)
    .switchIfEmpty(tenantNotExists(tenantId))
    .flatMap(tenant -> tenant.limiter(METRIC_ID))
    .flatMap(limiter -> difference > 0
        ? limiter.forQuota().increment(difference)
        : limiter.forQuota().decrement(-difference));
```

差额为零时直接结束；PUT 修改差额和删除释放由父类事件处理。额度来自平台规格。

[DemoQuotaConfiguration](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/configuration/DemoQuotaConfiguration.java) 在租户运行时存在时注册限制器 Bean。[DemoTransactionalCrudService](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/service/DemoTransactionalCrudService.java) 将业务写入和实体事件包在同一响应式事务中；[仓储事务处理器](../modules/examples/demo-manager/src/main/java/org/jetlinks/pro/demo/service/DemoRecordRepositoryTransactionPostProcessor.java) 为 Direct 更新计划字段的路径接入事务。

## 开发注意事项

- 资产类型、维度类型、控制器资源和菜单使用一致的业务标识；用户绑定的 `dimensionId` 使用班组业务 ID。
- 普通 CRUD 由 `AssetsHolderCrudController` 统一校验。成员接口查询的是用户，需在 Service 显式校验目标班组和用户资产范围。
- 成员候选限定当前应用。维度成员核验依赖 `user/query`；成员管理还需班组保存及维度保存／删除权限。
- 班组自身 `id` 映射保持只读；计划新增或变更归属时校验目标班组。
- 配额的新旧用量采用同一口径，业务写入、维度同步和用量变化共用事务。

应用隔离和模块边界要求见[应用开发注意事项](应用开发注意事项.md)。

## 最小主流程与接口

1. 新增班组：业务表写入后，同步动态维度实例。
2. 从当前应用成员中选择用户加入班组。
3. 新增计划：填写名称、负责班组和清单；后端校验班组并计量清单项数。
4. 为角色选择“所在巡检班组”，查询按成员关系和资产映射过滤；修改、删除计划相应调整用量。

页面经模块 `api/index.ts` 调用下列接口。CRUD 进入业务 Service 与 Repository；成员接口进入认证服务命令。下表 `{resource}` 为 `inspection-team` 或 `record`。

| 操作 | HTTP 接口 |
| --- | --- |
| 班组目录 | `POST /demo/inspection-team/_query/no-paging` |
| 计划分页 | `POST /demo/record/_query` |
| 新增、编辑、删除 | `POST /demo/{resource}`、`PUT /demo/{resource}/{id}`、`DELETE /demo/{resource}/{id}` |
| 已加入成员、候选成员 | `POST /demo/inspection-team/{teamId}/members/_query`、`POST /demo/inspection-team/{teamId}/members/_candidates/_query` |
| 加入、移出成员 | `POST /demo/inspection-team/{teamId}/members/_bind`、`POST /demo/inspection-team/{teamId}/members/_unbind` |

成员绑定和移出的请求体为用户 ID 数组，成员返回字段为 `id`、`name`、`username`。前端分页读取 `result.data`、`result.total`，班组目录读取 `result` 数组。
