# 应用开发注意事项

自定义应用上线必须遵守以下要求，避免影响产品已有功能、数据和其他应用。

1. **禁止修改或替换产品代码。** 包括产品已有前后端模块和公共组件；自定义功能在独立业务模块中实现，通过产品公开的扩展点接入。
2. **禁止引入平台已有服务的业务管理模块。** 如 `device-manager`、`saas-manager` 等。应用与其他服务保持解耦，通过公开接口或命令交互，不直接使用其他服务的内部 Service。
3. **禁止改动产品已有权限和认证机制。** 不修改产品公共权限定义及其他应用的授权数据，不关闭或绕过鉴权、租户和应用隔离；新增业务接入平台现有权限体系。
4. **禁止改动产品已有表和业务实体。** 不修改产品表结构，不继承产品业务实体扩展字段，不直接读写其他服务的数据表；业务扩展使用自有表，通过产品对象 ID 关联。
5. **禁止改动产品全局配置和依赖。** 不修改产品的认证配置、网关路由、服务发现或依赖版本，不通过全局拦截器、同名 Bean 覆盖等方式改变产品行为。
6. **禁止自定义标识与产品冲突。** 服务名、接口路径、表名、权限标识、缓存键和消息消费组应区分应用，避免覆盖现有功能、串数据或分走产品应消费的消息。
7. **禁止清理或覆盖共享数据。** 不得清空共享数据库、Redis 或公共文件目录；应用初始化、升级和卸载只能处理本应用拥有的数据，不得重置产品数据或停止其他服务。
8. **禁止无控制地占用系统资源。** 大批量查询、导入和远程调用必须控制批次、频率及并发，不得阻塞公共处理线程，或因海量日志耗尽磁盘、因无限任务耗尽连接和内存。
9. **禁止后台任务失控或越界。** 定时任务、事件监听和消息消费应限定业务处理范围，不得因多实例重复执行、循环发消息或无限重试持续影响整个系统。
10. **禁止暴露平台管控能力。** 应用不得开放设备产品新增、网络组件、接入网关等平台管理功能及相关信息。

## 自定义资产接入

- 业务实体通过 `@Asset` 声明资产类型，对外接口接入 `AssetsHolder`；菜单、按钮与后端资源及操作标识保持一致。
- 应用内操作保留当前身份、租户和应用 Scope；跨服务使用公开接口或命令，不切换为管理员身份代执行。
- 用户绑定维度与角色授予数据范围分别完成，不能将成员关系直接视为功能权限。
- **自定义维度暂不支持下级资产控制。** 数据权限按当前明确的资产映射使用。
